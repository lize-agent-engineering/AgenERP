**②端只读**——本阶段 Agent 不写任何业务数据。

## 本阶段的三条硬约束（违反即停机，不是风格建议）

**① 判据不许只验「调得通」。**（CP9 继承项①）
退出码 0 与「跑了且过」不是一回事。P1 尤其危险：**「Agent 答对了」与
「Agent 蒙对了」在结果层面长得一模一样**。每条判据都要能区分这两者。

**② 预测在前、结果在后、逐条吻合。**（CP9 继承项②）
凡实验性质的工作项，假设**在跑之前逐字写死**，事后逐条对照，不许事后改写。

**③ 规则能覆盖的流程不 Agent 化。**（D-15）
面对任一环节先问：**「这一步的判断能不能写成确定性规则？」** 能写就写成规则。
只有输入模糊、路径不可预先枚举、或需按中间结果动态改变后续动作时，才交给模型。
**反向边界**：自然语言理解、多跳路径选择、归因叙述的组织**枚举不完**，
强行规则化会退化成脆弱的关键词匹配。判据是「路径能否预先枚举」，不是「看起来复不复杂」。

**④ 以本项目的实测为准。**（D-16）
外部基准、他人评测、厂商声明，只能作**假设的来源**，不能作**结论的依据**。
引用任何数字前先问：**「这个数字是在本项目、本数据集、本任务上跑出来的吗？」**
不是，就写成「据某处，推测……，待复验」，不写成结论。
**已发生的实例**：外部基准给 `qwen3.6-plus` 84.1%，**本项目任务上 **4/6**（`门禁off 3/3` + `门禁on 1/3`）⚠️ 此数经两次更正：先记 2/6、后记 1/6，均因判定正则漏掉一种拆法，见 STATE §2 同日更正行**。

## ⚠️ P1.7 的设计前提已被 P1.0 动摇（动手前必读）

P1.7 原本的前提是「**便宜模型 + 强门禁**」可用。P1.0 的 2×2 网格与人侧独立复核
都不支持它：

| 模型 | 门禁 | 正确 | 平均工具调用 |
|---|---|---|---|
| qwen-plus | off | 0/3 | 5.3 |
| qwen-plus | **on** | 1/3 | 10.0 |
| qwen3.6-plus | off | 1/3 | 10.3 |
| qwen3.6-plus | **on** | 0/3 | 10.7 |

四格合计 **2/12**。门禁**没有把任何一个模型带到可用水平**；强模型格加门禁反而更差。

⚠️ 每格 3 次**只够看方向，不够算比率**。正确表述是「该命题在这道题上未获支持，
且强模型格有反向证据」，**不是**「门禁使正确率从 0% 升到 33%」。

**处置需人定**（STATE §3 有 open 条目），三条路：提高模型档位并重测 /
改进门禁设计 / 承认这道题需要更强模型并按实测重设成本上限。
⚠️ **不得**因为「成本模型不好看」而放宽 P1.0 的判定标准。

## 测试阶段取模型的顺序（D-17）

**保证质量的前提下，优先用百炼上免费额度最先过期的模型。** 额度用掉或作废。

⚠️ **必须用带日期的版本号**：裸别名 `qwen3.7-plus` 报 `Free quota exhausted`、
裸 `qwen3.7-max` 报 403，而 `qwen3.7-plus-2026-05-26` / `qwen3.7-max-2026-06-08`
可用且额度充足 —— **别名与带日期版本走不同的额度池**。

⚠️ **只作用于测试/实验阶段**。生产路由的默认模型由能力档案决定，不随日历跳变。
