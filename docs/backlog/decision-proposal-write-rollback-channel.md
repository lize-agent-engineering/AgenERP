## 要决的是什么

P3.2 的实测把 §7.1 那套 savepoint 回滚语义**在本仓分成了两半**：

- **进程内成立**，逐项复现，含「不产生单号空洞」；
- **我们的工具层够不着它** —— 前提 0，两条互相独立的腿（跨连接不可见 · POST 提前 commit）。

⇒ 写契约 v1 的 `on_violation` 在 REST 面上**只能**是 `abort_before_side_effect`。
`rollback_and_report` 与 `ON_VIOLATION_VALUES` 里那个取值今天是**孤儿**。

**要人决的是：接受这件事，还是换一条通道把它变成成立的。** 三条路如下。

## 三条路

### (A) 自有 frappe app —— 把工具层搬进站点进程

把契约执行放进一个自建的 frappe app 里，通过一个白名单 `@frappe.whitelist()` 方法
一次请求跑完「前置 → 执行 → 后置 → 回滚」。这样 savepoint 全程在同一条连接、
同一个请求内，前提 0 的两条腿都不成立，§7.1 的语义**原样可用**。

- ✅ 唯一能让 `rollback_and_report` 真正成立的路。
- ❌ **产品形态变了**：今天 `agenerp/` 是站点外的纯 Python 包，零站点态
  （`agenerp/oob.py` 模块头第 3 条那条界线就建立在这上面）。装一个 app 进站点，
  意味着「系统形态由每家企业自己长出来」这件事多了一个必须先装的前置件。
- ❌ 与红线 7 的界线要重新划一次：红线 7 禁的是 Agent **生成**运行时 Server Script；
  自有 app 是人写的代码、走 GitOps 部署，**不是**红线 7 禁的东西 ——
  但这条界线今天没人明文写过，走这条路要先把它写下来。
- ⚠️ 迁移成本：`tests/gates/**` 里所有走 REST 面的判据要重新想在哪一层跑。

### (B) 带外 `bench execute` —— 复用 `agenerp/oob.py` 那条通道

把写操作从 REST 面挪到带外通道，一次 `bench execute` 里跑完整个四阶段。

- ✅ 通道**已经存在**且已被 P2.5 用过，前提 0 同样不成立。
- ❌ `ALLOWED_CALLS` 的设计前提是**「函数名 → 钉死的 kwargs」**（模块头约束 2）。
  写契约要传的是**任意单据内容**，钉不死 —— 白名单一旦退化成「能传任意 payload」，
  模块头约束 3 那条与红线 7 的界线就没了。
- ❌ 它要 `docker compose exec`，即**产品运行时依赖宿主的容器编排**。
  今天只有运维侧的巡检在用它，把业务写入也架上去是另一回事。
- ⚠️ 这条路等于把 (A) 的代价换个位置付：仍然要在站点侧有一段自己的代码。

### (C) 不做回滚 —— 把后置能预算的**前移成前置**

承认「后置断言不成立时回滚」在这条通道上不可得，改成：
凡是**执行前能算出来**的约束一律做成前置条件（一个请求都不发），
剩下真的只能事后知道的，`on_violation` 一律 `abort_before_side_effect` + 留痕 + 报人。

- ✅ **零通道改动**，今天就能落地；与 `agenerp/tools/runtime.py` 的四阶段结构完全相容
  （它本来就没有回滚阶段）。
- ✅ 与 §7.3 那句「`before_submit` 是最后防线，永远保留，永远生效」同向：
  契约前置**镜像并前移**站点门禁，本来就是这个思路。
- ❌ **有一类失败它接不住**：执行成功但后置不成立（例如提交后 GL 借贷不等）。
  那种情况下单据已经落库，只能靠人用 cancel / amend 收拾 ——
  而 §7.1 逐字说过 **cancel 不是契约的补偿机制**，那是用户的业务动作。
- ❌ 倒填那条路径尤其难受：`Repost Item Valuation` 那一行**已经提交下去了**
  （见实测 §3），前移预算算不出「重估值之后账对不对」。

## loop 的意见（**只是意见，不是决策**）

**(C) 作为 v1，且把 (A) 显式登记成 v2 的候选**，理由三条：

1. P3.1 的验收是 `pytest tests/contracts/test_write_contract.py -q` 退 0 ——
   它判的是**契约结构**，(C) 完全够；(A)/(B) 都要先改产品形态，
   那是比 P3.1 大得多的决定，不该被一条写契约顺带决定。
2. (C) 是唯一**不动通道**的路，因此它**不预支**任何未来选择：
   将来选 (A)，前移过的前置条件一条都不浪费。
3. 反过来不成立：先走 (A) 再退回 (C)，中间那段站点内代码是纯损耗。

⚠️ **但 (C) 有一条必须同时接受的代价**：`ON_VIOLATION_VALUES` 里
`rollback_and_report` 会**长期是孤儿取值**。建议**不要删它**，
而是在校验器里对写契约**显式拒绝**它并给出理由（指向本文件）——
删掉的话，将来选 (A) 时没人记得曾经有过这个取值和它为什么消失。

## 与这条决策绑在一起的三个结构位（无论选哪条都要做）

它们**不预设**上面三选一的结果，但 P3.1 落地时一起动：

1. `WRITE_CONTRACTS` 新族并入 `ALL_CONTRACTS`，形状照 `INSPECTION_CONTRACTS`
   （`agenerp/tools_readonly.py`）。
2. `ToolContract.side_effects` 的**实际使用** —— 今天从未非空，而 §7.1 逐字要求
   「写契约必须声明它是否产生事务外副作用」。实测已经给出了第一条要声明的东西：
   **倒填的 `Repost Item Valuation`**。
3. `approval` 改成**封闭取值表** —— 今天只有 `not_required` 一个字符串常量、
   不是元组，而 `risk` / `on_violation` 都是封闭元组。这是 P3.4 的第一个结构位。
