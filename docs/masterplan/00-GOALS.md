## 1. 北极星（逐字背诵，不得转述）

> **让 ERP 的呈现层、语言层、判断层由 Agent 承担，让系统形态由每家企业自己长出来——且每一次生长都是可 diff、可回滚、可迁移的产物。**

这句话的三段各有出处，不是修辞：

| 段 | 依据 |
|---|---|
| 「呈现/语言/判断三层」 | 实测结论：ERP 不缺功能，缺可用性与适配性，而这三层恰好是 LLM 的主场（`REF:PROBLEM`） |
| 「形态自己长出来」 | 设计公理 3（`REF:AXIOMS`） |
| 「可 diff、可回滚、可迁移」 | 与低代码平台的根本分歧；也是防定制死亡螺旋的**全部理由**（`REF:ANTI-SPIRAL`） |

**删掉第三段就不是这个项目了**——那是低代码平台。任何时候发现工作项与第三段无关，先停下来查 02-WBS 有没有走错行。

## 3. 阶段目标各一句（用于快速定位「我在哪」）

| 阶段 | 一句话 | 风险等级 |
|---|---|---|
| **P0** | 把「可验证」做出来——不引入任何 LLM | 无 |
| **P1** | 只读的解释与洞察——第一个可演示的东西 | 只读 |
| **P2** | 视图生成与新前端——项目最具说服力的演示 | 生成视图 |
| **P3** | 操作 Agent——开始产生生产力 | 写业务数据 |
| **P4** | 形态 Agent——最难也最值钱 | 改系统形态 |
| **P5** | 评测与编排——把前面的能力锁住 | 回归 |

**风险递增，绝不跳级**（路线图原则 2，`REF:ROADMAP-PRINCIPLES`）。任何「先做 P3 的一小块」的提议都是跑偏，直接拒绝并记入 STATE §3。

## 4. 公理与非目标（只引用，不复制）

- **三条设计公理** → `REF:AXIOMS`。其中第 1 条（护栏长在执行路径上，不写在提示词里）**同时是本主计划自身的方法论**：所以门禁是脚本判退出码，不是 prompt 里写「请如实汇报」。
- **明确的非目标** → `REF:NONGOAL`
- **不做的事（已知的坑）** → `REF:ROADMAP-DONT`
- **许可：GPL-3.0，不设 CLA，放弃双许可** → `REF:LICENSE`

发现工作项落在非目标里 → 立即停手，记入 STATE §3 `needs-human`，不要「顺手做一点」。

## 5. 措辞纪律（写文档、写 commit、写复盘时都适用）

建设前验证的十条假设是 **每题各跑 1 次** 得到的（`REF:PBV-RESIDUAL`）。因此：

| 禁止 | 允许 |
|---|---|
| 「已证明」「显著优于」「统计上」 | 「单次实测」「本轮实测中」「n=1，未做重复」 |
| 「门禁可以补偿模型能力落差」 | 「L1/L2 门禁在本地 14B 上未能救回多跳探针；L3 本轮未跑完」 |
| 「定制包可迁移（已验证）」 | 「可迁移是从 upsert 幂等性推断的，未建第二站点实测」 |
| 「抗注入已通过」 | 「L0 只读 Agent 上 4/4 抵抗；写权限下未测」 |

**超出证据强度的措辞本身就是跑偏**，且比代码错误更难发现。复盘时（CP9）专查这一项。

## 6. 背诵条款（强制）

1. **每个监督会话的第一条回复**，必须逐字复述 §1 的北极星句，再谈别的。做不到说明上下文没建立，停下来重走 [README.md](./README.md) §2。
2. **每个 `mission.json` 的 `goal` 字段**必须内含 §1 北极星原文（可加阶段限定，但不得改写原文）。
3. **每次阶段关口复盘（CP9）**，第一项是对照 §2 逐条问「这一阶段把哪一条往前推了」。答不上来 → 该阶段的 WBS 行有问题，不是复盘有问题。
