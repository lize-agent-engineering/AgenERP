# 03 · 技能 → 关口映射

> **两条铁律**
> 1. 技能只在**监督侧（角色 A）**触发。loop 内（角色 B）零外部技能依赖，一律走 fork 的 `prompts/`——外部技能在无头环境里既不稳定，又会把不可控上下文塞进执行器。
> 2. **每个关口都必须能在没有技能的情况下走完。** 附录 A 的内置清单是等效替代，不是安慰奖。技能装不上 → 走清单 → 继续干活，**不阻塞**。

## 附录 A · 内置等效清单

### A1 · 质询十问（等效 grill-me）

对着被质询对象逐条回答，**答不上来就是发现**：

1. 这一项的**验收命令**是什么？跑一遍给我看退出码。
2. 如果这一项做完了但项目仍然失败，最可能是哪一步骗了我们？
3. 这里引用的结论，是**实测**还是**推断**？实测的话 n 是多少？
4. 有没有哪句话的措辞强于证据（见 [00-GOALS.md](./00-GOALS.md) §5）？
5. 这一项和北极星的哪一段直接相关？答不出 → 该项可能不该做。
6. 谁能推翻这个判定？如果只有 AI 自己能判定，说明缺门禁。
7. 失败时会**怎么被发现**？是自动停机，还是要人碰巧看到？
8. 前置条件里有没有「假定环境已就绪」这类没写死的依赖？
9. 这一步引入了几个新的活动部件？能不能少引入一个？
10. 如果三个月后一个全新会话接手，只读这份文档能不能干？缺哪一句？

### A2 · 规格清单（等效 tospec）

`标题 / 动机（挂 WBS 行 ID）/ 范围内 / 范围外 / 验收命令（必填）/ 前置 / 失败时的可观测信号 / 引用（走 REF）`。**范围外一栏空着即视为没写规格。**

### A3 · 计划清单（等效 writing-plans 的最小集）

分步；每步有可跑命令；每步有可观测的完成信号；标出哪一步不可逆；标出哪一步需要人在场；末尾 `## Closure` 段（mission-driver 的 `CLOSURE_SCRIPT_CHECK` 会数这一段）。

### A4 · 红测试清单（等效 TDD）

1. **先跑一遍，确认它红**——没红过的测试不算测试。
2. 断言的是**行为**（字段真的消失了吗），不是实现（调用了几次函数）。
3. 失败信息里必须能看出「期望什么、实际什么」。
4. 不依赖网络/时间/随机；需要活站点的标 `-m live`，进 L2 层。
5. **人终审后才入 `tests/gates/`**——入库即成为裁判，此后 loop 不得触碰。

### A5 · 评审清单（等效 /code-review）

改动是否只做了 plan 说的事；有没有顺手改判据；错误路径有没有被吞；新依赖是否必要；是否有本地能过、CI 会挂的写法（路径、时区、大小写敏感）。

### A6 · 三连败诊断（等效 systematic-debugging）

**先复现，再假设。** 顺序固定：原样复跑失败命令 → 记录完整输出 → 写下一句话根因假设 → 设计一条能证伪它的命令 → 跑 → 记结果。**连续两个假设被证伪就停手，转 needs-human**，不许继续猜。

### A7 · UI/UX 清单

对照 P2 的可机器判定基线（渲染元素 > 0、空壳工作台 = 0）；键盘可达；对比度；空状态有出路；错误信息说人话；**未支持的一律落回 Desk**，不做半成品。

### A8 · 数据呈现清单

每张图注明**取数命令**；坐标轴有单位；不用双 Y 轴制造相关性；n 小于 5 时**直接标 n**（本项目所有 spike 探针 n=1）；深浅色都能看。

### A9 · 复盘模板（CP9）

```
1. 对照 00-GOALS §2：这一周/这一阶段把 S1–S6 的哪一条往前推了？（答不上来 = WBS 行有问题）
2. 停机次数、各自触发条件、平均恢复时长
3. 门禁误判：判 fail 但其实是对的，有几次？判 pass 但其实错了，有几次？（后者是最危险的数字）
4. 成本：本期消耗 vs 阈值
5. 措辞审计：本期文档/commit 里有没有超出证据强度的说法（00-GOALS §5）
6. 方法论续用复评（阶段关口必答，判据见 04-RUNBOOK §7）：
   · AGE / mission-driver —— 续用 / 停用？
   · LoopX —— 续用 / 停用？
7. 下一期只做一件最重要的事，是什么？
```

### A10 · 完成前核验（等效 verification-before-completion）

宣称完成前，**同一条回复里**必须出现：跑过的命令原文、退出码、commit sha。三者缺一，把「完成」改成「我认为完成，待验证」。
