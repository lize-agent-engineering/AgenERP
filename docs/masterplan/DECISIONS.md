# 决策台账

> **规则：本文件只增不改。** 已登记的决策不得被任何会话（包括你）擅自重开——重开只有一条路：人明确说要重开，然后在 §3 追加一条 `R-x` 记录，写清新证据。
> 「我觉得换个做法更好」不是新证据。**只有触发了该决策自带的翻案条件，才允许重开。**
>
> **「只增不改」的确切边界**（T3 演练暴露的歧义，2026-08-20 补）：
> - ✅ **允许**：在某条决策的表格末尾**追加**一行「复核 / 实测结果」，写清日期与命令证据。W0.1 那类「结论写回 D-1」的动作就落在这里。
> - ❌ **禁止**：改写或删除任何已有行；改动「翻案条件」的措辞；在没有人拍板的情况下把结论改成相反的。
> - 追加不等于重开。**重开只能由人在 §3 写 `R-x`。**

### D-8 · OAuth 过期照旧由人处理，不换认证、不加通知

| | |
|---|---|
| 决策 | 维持订阅 OAuth。**不**换 API key 认证，**不**加停机推送通知 |
| 依据 | 用户 2026-08-22 明示「不加，继续推进即可」 |
| 背景 | 2026-08-22 一天内 OAuth 过期 **4 次**（约每 4–8 小时一次），每次都要人在场登录。这与 7×24 无人值守直接冲突 |
| 曾评估过的两条路 | ① 换 `ANTHROPIC_API_KEY`：没有过期问题，但变成按 token 计费——而 D-3 选订阅正是为避开它，等于**用钱换无人值守**；② 加停机推送：不解决中断，只缩短发现延迟 |
| 现状够用的理由 | 停机机制已能在**第一分钟**识别认证失败、落 `.mission-halt.json`、拒绝后续重启。代价是「等人」，不是「空转一夜」——最贵的那个失败模式已经关掉了 |
| 翻案条件 | 出现下列之一：① 无人值守时长成为阶段验收的硬指标（如 P5 的连续评测）；② 过期频率进一步升高到每轮都撞；③ 计费口径变化使 API key 不再意味着额外成本。**不得因为「有人觉得烦」而重开** |
