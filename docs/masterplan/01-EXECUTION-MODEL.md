# 01 · 执行模型

> 谁有权做什么、状态归谁管、出事怎么交接。**本文件规定的是权限边界，不是建议。**

---

## 1. 双角色

| | **角色 A · 监督会话** | **角色 B · loop 内执行步骤** |
|---|---|---|
| 形态 | 交互式 Claude Code 会话，**人在场** | mission-driver 通过 `--driver claude` 拉起的无头进程，**无人在场** |
| 入口 | [README.md](./README.md) §2 的 RESUME 命令 | `./mission-driver.sh <mission>` |
| **可以** | 改 WBS 行、改 mission 配置、装/用技能、跑关口实验、判断 needs-human、写 DECISIONS 的请求 | 写业务代码、跑 `pytest`/`ruff`/`mypy`、提交、按门禁失败输出自修复 |
| **禁止** | 代替人拍板已登记的决策（见 DECISIONS §3 重开规则） | ① 改 `tests/gates/**`（触碰即停机）② 改 `docs/masterplan/**` ③ 改 `missions/*.json` ④ 改 CI 配置 ⑤ 新增外部技能依赖 ⑥ 自行宣称门禁通过 |
| 状态写权 | 可写 STATE §1/§2/§3、可写 LoopX todo | **只能**通过 `GATE_VERIFY` 的退出码间接留痕；不得手写 STATE |
| 判定权 | 对「要不要做」有判定权 | **对「做没做成」没有判定权**——由 `gate-verify.mjs` 复跑子进程的退出码裁决 |

> 角色 B 的禁区清单必须逐字进 `AGENTS.md`（Day 0 `W0.5`）。禁区是护栏长在执行路径上的体现——**写在 prompt 里的禁令不算数**，前三条各有对应的确定性拦截：①`gate-verify.mjs` 的 `git diff --name-only` 检查 + CI 复跑；②③④ 靠 pre-commit hook + CI 的 path 白名单。

## 2. needs-human 五步交接

**触发条件**（任一）：同一 plan 连续 3 轮 `GATE_VERIFY` fail ｜ `git diff` 触及 `tests/gates/**` ｜ 单 mission 累计成本超阈值（数字由 `W0.0` 定出）｜ CI 连续 2 轮红。判据正文见 `REF:HALT`。

| 步 | 谁做 | 动作 | 产物 |
|---|---|---|---|
| 1 | 引擎 | 停机，**不再重试**，保留现场（工作区不 reset、不 stash） | 进程退出码 + 日志路径 |
| 2 | 引擎/脚本 | 往 [STATE.md](./STATE.md) §3 追加一条 `needs-human`：触发条件、WBS 行 ID、最后一条失败命令**原文**、退出码、相关 commit sha | STATE §3 一行 |
| 3 | 角色 A | 复现：**先原样复跑那条失败命令**，确认失败真实存在再分析。复跑不出来 → 记「不可复现」，不许猜 | 一条证据行 |
| 4 | 角色 A（人参与） | 处置**四选一**：`修 WBS 行`（判据本身错了）/ `修实现`（判据对，代码错）/ `重开决策`（须人拍板，走 DECISIONS §3）/ **`不可复现 → 关单`**（第 3 步复跑不出原失败：退出码或输出与记录不符、绑的 sha 不存在、该 WBS 行根本没开工）| 处置记录 |
| 5 | 角色 A | 解除：把 §3 那条标 `resolved`（**不删**），STATE §1 更新下一项，重启 loop | 一条证据行 + 重启命令 |

**第 3 步是防跑偏的关键**：不复现就分析，等于让模型在想象的失败上工作。
第 4 步的「不可复现」是 2026-08-20 的 T4 演习补的——原本只有三个选项，全都预设「失败是真的」，会话只能在三个错误选项里挑一个。**一条处置路径缺席，和判据写错一样危险。**

## 3. 监督会话的生命周期

### 3.1 开场（RESUME）——必须完成四件事再谈别的

1. 逐字复述北极星（[00-GOALS.md](./00-GOALS.md) §1）
2. 读 [STATE.md](./STATE.md) §1 快照，说出**当前阶段 / 当前 mission / 上一条证据行**
3. 从 [02-WBS.md](./02-WBS.md) 指出**下一个未阻塞的工作项 ID**
4. 给出该项的**验收命令原文**

四件事在**同一条回复**里给全。给不全 = 上下文没建立，重走 README §2，不要往下做事。

### 3.2 收场（Epilogue）——强制

会话结束前（或做完任一 WBS 项时），必须往 STATE §2 追加**证据行**，格式固定：

```
- 2026-08-20T18:40Z · W-1.2 · `tools/check-masterplan-links.sh` → exit 0 · sha 1c622c8 · 下一项 W-1.4
```

**四个字段缺一不可：时间戳、WBS 行 ID、命令 + 退出码、commit sha。** 没有退出码的行不算证据，算感想。

`sha` 取值约定：**动作行**用该动作发生时的 `HEAD` 短 sha（它回答「当时仓库是什么状态」）；**收尾行**用刚产生的那个 commit 的 sha。查仓库外部世界的动作（可得性复核、线上探针）同样绑当时的 HEAD。

### 3.3 单会话单工作项

**一个监督会话只推进一个 WBS 工作项。** 做完就收场、写证据行、结束。理由：会话越长越容易把「顺手改点别的」正当化，而长会话的上下文压缩恰好会丢掉最早的目标。

## 4. LoopX 分层契约（防止重蹈 OpenSpec 双状态机覆辙）

| | 拥有什么 | 不得触碰 |
|---|---|---|
| **LoopX** | **WBS 项级 / 跨会话状态**：一个 LoopX todo = 一个 mission run 或一个人工项；配额决策（`loopx quota should-run`）；跨会话续跑 | mission 内部的 plan 状态、门禁结论 |
| **mission-driver** | **mission 内执行状态**：plan 的 draft/exec/closure、`GATE_VERIFY` 判定 | 跨会话的「下一步做什么」 |
| **STATE.md** | **人类可读投影**（LoopX 官方模型即「看板是投影，状态内核才是真相源」） | 不是真相源；与 LoopX 冲突时以 LoopX 为准 |

**写回方向单一且不经 AI**：`GATE_VERIFY` 的退出码由包装脚本写回 LoopX 证据，**AI 不得转述结果**。任何「让模型把结果同步一下」的做法都是把确定性换回概率性。

**降级路径**：LoopX 不可用（未装、崩了、按 D-6 退出判据被停用）→ 无损退回手工 STATE.md 纪律。**STATE.md 的格式在两种模式下完全相同**，这是降级无损的前提。

## 5. 执行器沙箱规范（`--driver claude` 必须遵守）

实测陷阱（`REF:SPIKE02-MODELS`）：在项目目录里直接跑 `claude -p`，CLI 会加载该目录的 `CLAUDE.md`、SessionStart hook 与 skills——**单轮多出约 37,000 token 的无关上下文，并干扰模型对协议的遵守**。7×24 下这既是成本灾难，也是行为污染源。

因此 loop 拉起执行器时必须：

| # | 规范 | 检查方式 |
|---|---|---|
| 1 | 在**空临时目录**里启动进程（`tempfile.mkdtemp`），不在仓库根目录 | 进程 cwd 断言 |
| 2 | 隔离 `HOME`（或等价配置根），**不继承用户级 skills / hooks / 插件** | 首轮 token 数与空目录基线相差 < 5%（`W0.8b` 验收） |
| 3 | 需要的文件**显式传入**，不靠工作目录自动发现 | prompt 里列出文件清单 |
| 4 | 扣除固定脚手架开销（实测约 1,561 token）后再算成本 | 成本统计脚本 |

> 这一条同时是 D-3 的实现约束：`--driver claude` 若照抄 pi/cline 分支而不做隔离，会把 loop 变成一台烧钱机器。

## 6. 防漂移四则（贴在每个监督会话开头）

1. **背诵目标** —— 开场第一句是北极星原文，不是「好的，我来看看」。
2. **只认退出码** —— 「测试过了」只有一种证据：命令 + `echo $?`。模型（包括你）的自述一律不算。
3. **不碰 `tests/gates/`** —— 判据是裁判。改裁判等于作弊，触碰即停机。
4. **单会话单工作项** —— 做完一项就收场写证据行。想顺手做的第二件事，写进 STATE §3，让下一个会话做。
