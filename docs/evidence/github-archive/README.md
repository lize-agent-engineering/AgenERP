# GitHub 侧证据存档（2026-08-24 删库重建前抓取）

## 为什么有这个目录

台账（`STATE.md` / `DECISIONS.md` / 各 plan 的 `## Closure`）里引用了大量
GitHub 侧的证据：CI run ID、job ID、PR 号。它们是「**预测在前、结果在后、
逐条吻合**」这套自证方式的落点 —— CP9 复盘判 AGE「续用」正是靠这类记录。

2026-08-24 因隐私清理（个人邮箱在 `refs/pull/*` 里删不掉）**删库重建**，
这些 URL 全部失效。抓取存档，使引用仍可追溯到**结论**，尽管链接已死。

## 文件

| 文件 | 内容 | 条数 |
|---|---|---|
| `workflow-runs.jsonl` | 全部 workflow run 的结论、分支、事件、时间 | 135 |
| `pulls.jsonl` | 全部 PR 的标题、状态、合并时间、分支 | 13 |
| `referenced-jobs.jsonl` | **台账实际引用到的** run 之下的全部 job 明细 | 631 |

## ⚠️ 存档保住了什么、没保住什么

**保住**：run/job 的**结论**（success / failure）、名称、时间、所属分支。
凭这些仍能核对「某次变异实验是不是真的红了」。

**没保住**：**日志正文**。GitHub 的 run 日志无法批量导出，删库即消失。
因此「日志里逐字写着什么」这类引用**降级为不可复核** —— 照实登记，
不得当作仍然可验。

## 对读者的话

引用里出现 `run 32570942284` 这类 ID 时，去 `referenced-jobs.jsonl` 里查
`run_id`，能拿到那次运行的 job 结论。`html_url` 字段指向的地址**已失效**，
保留它只是为了标明证据原本的位置。
