## 2. P1-3（一次真实解释在 runner 上的秒数）

- **2a** 预期能从红 run 的 `失败取证` 步尾部「解释服务容器最近 60 行」里找到请求起止时间戳。
- **2b** 若找得到，预期单次真解释墙钟 **> 30 秒**（这正是 B3 成立的判据）。
- **2c 🔴 若 B3 被证伪，预期看到的是**：日志里那次真解释的墙钟 **< 30 秒**（例如 5–20 秒）而判据仍然红，
  ⇒ 说明红不是「解释太慢」，30 秒的客户端预算够用，红因在链路而不在耗时。
  **这一格是本预测里最重要的一格**：只写「我猜它会超时」等于把取证写成自我实现。
- **2d** 也可能日志里根本没有时间戳（容器日志默认无时间前缀）⇒ 照实写「未测出」，不许用「大概很慢」代替。

## 3. P1-4（本机把 B3 单独逼出来）

- **3a 🔴 已知阻断，先写死**：本机 **没有** `AGENERP_LLM_API_KEY` / `DASHSCOPE_API_KEY`
  （`env` 实测只有 `AGENERP_LLM_MODEL` 与 `DASHSCOPE_BASE_URL`，`.env` 只有三个键、无密钥）
  ⇒ **本机发不出真解释**，服务会走 503 分支。
  ⇒ 预期 P1-4 的「测两条判据各自的墙钟」**做不成**，只能记「未做 —— 本机无模型密钥，密钥只有人有」。
- **3b** 但本机**不需要密钥**也能起栈 ⇒ 预期能拿到 P1-5 ②③ 要的 `RestartCount` / `StartedAt` / `Health.Status`。
- **3c** 预期本机起栈会复现「frappe 系容器在 `--wait` 返回后再重启一次」。
  **⚠️ 反侧预期**：若本机**不**复现，只能写成「本机不复现」，**不得**写成「重启窗口被证伪」（D-16）。

## 4. P1-5（起栈时序：证实或排除）

- **4a** `docker compose ps` 里预期看得到 `agenerp-serve` 与 `backend` 的相对起动次序线索。
- **4b** 预期 `agenerp-serve` 确实起得比 `backend` 早（`depends_on` 只有 `create-site`，B4 后半句实读为真），
  **但预期这一点并不造成红** —— 因为 nginx 已是 `resolver` + 变量 `proxy_pass` 形式（B4），
  `agenerp-serve` 缺席时只有 `/agenerp/` 回 502，而红的形态是超时不是 502。
  ⇒ **预期「起栈时序」这条方向被排除或降级为「无证据」**。
- **4c 🔴 反侧**：若某次红的 traceback 是 502 / `BadStatusLine`，则起栈时序**坐实**，预期 4b 不成立。
