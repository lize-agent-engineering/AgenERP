- **Phase 1 · 实现 `agenerp.pack.normalize`**：纯函数、零第三方依赖、不改入参、幂等。
  - 「易变」的判定口径定为**按键名子串黑名单递归剥离**，落点是模块级常量
    `VOLATILE_KEY_SUBSTRINGS = ("modified", "creation", "owner", "_comments")`。
    子串而非精确键名，是因为门禁断言 2 对 `repr(normalize(a))` 做**子串**检查——真实 Frappe 导出里的
    `modified_by` / `owner_id` 只要留着，那条断言照样红。
    否决的备选：按「两次导出值不同」自动推断易变字段（调用方拿不到两份样本，且会把真实业务变更误判为噪声）。
  - 排序两层都做：字典递归重建为**按键名排序**（`==` 不看键序，但 `repr` 和 git diff 看）；
    「元素全是 dict 的列表」按稳定身份键排序，优先 `fieldname`，缺失时退化为 `(空串, repr(条目))`——
    保证无身份键的条目也不因输入顺序抖动，且混合条目不会在排序时撞上类型不可比。
  - **标量列表不排序**（Select 的 options 顺序是业务语义，不是噪声）；tuple 归一为 list，
    否则同样内容的两份导出会 diff 出容器类型差异。
