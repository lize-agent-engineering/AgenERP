```
bash scripts/verify-gitops.sh → 退出码 0（连跑两次都 0）
```

## 🔴 两件值得下一个人知道的

### ① 第四步是 P0.5 那笔 deferred 的正身，不是我临时扩的范围

`execute_plan` 原来对 `creates` **当场抛**，而 P0.5 把它 deferred 时**写死了重开条件**：

> 重开事件：出现需要用包在站点上**建**字段的调用方时。

「把包 apply 到一个还没有该字段的站点」就是那个调用方。⇒ 建字段的执行路径是本项的正身工作量。
**`updates` 那一半仍然显式拒绝**（今天没有调用方），纪律一个字没松。

**先建后删**：两者都失败得起，但代价不同 —— 建失败时什么都还没删。
破坏性动作放在增量动作之后，是本层在「没有事务」这个前提下能做的唯一取舍（事务归 P3.1）。

### ② 第四步一度**假绿**，靠一条前置/隔离断言咬住

第一次跑 ①②③ 全过、第四步也报「gitops.test 上长出了字段」——**只有「frontend 不受影响」红了**。

```
经 nginx(18080)，Host=frontend    -> 有 Item DocType
经 nginx(18080)，Host=gitops.test -> **也有 Item**   ← 那站点没装 erpnext，不该有
```

nginx 的 `FRAPPE_SITE_NAME_HEADER=frontend` 把**所有**请求钉在 `frontend` 上，
而 backend 没有对宿主发布端口 ⇒ 字段实际建在了 `frontend`。

**没有那条隔离断言，这一步会报成功，而它连第二个站点都没碰到。**
⇒ 「先断言本来不存在」「先断言那边也没有」这两条前置，是四步里最容易省、也最不能省的东西。

修法：给 backend 加一格**只绑环回**的端口（人 2026-08-28 裁定）。
**不能**改 `FRAPPE_SITE_NAME_HEADER=$host` —— 浏览器判据打 `127.0.0.1:18080`，
Host 就是 `127.0.0.1`，Frappe 会去找一个叫 `127.0.0.1` 的站点，
正是 `agenerp/site.py` 模块头记着的那个坑。
