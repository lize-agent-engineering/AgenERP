## 🔴 三件值得下一个人知道的

### ① 另起契约族，不并进那十个 —— 两条理由缺一不可

- **设计**：`tool_schemas()` 直接按 `READONLY_CONTRACTS` 生成**模型可见**的工具面。
  人裁定 `schema.drift` 不进模型面（D-15：巡检是规则面，P1.5 的巡检器就是零 LLM 的纯规则引擎）。
  分族之后，「不在模型面」**由构造保证** —— 靠 `EXCLUDED_TOOLS` 排除是让机制和意图打架，
  **排除表漏一行就漏出去了**。
- **红线**：`tests/tools/test_live_conformance.py` 是门禁断言体
  （被 `tests/gates/test_tool_execution_live.py:57` 按路径加载），它逐条验的正是「**十个**工具」。

⚠️ **配对不变量没放松**：`ALL_CONTRACTS` 与 `EXECUTORS` 仍然双向一一对应。

### ② 后置事实是**算**出来的，不是自报的

纪律照 `schema_search`（它的 `returns_candidate_list_not_single_pick` 算的是
`len(candidates) == len(matched)`）。这里把真正发出去的带外命令逐条记下来，两条后置都从那份记录算。
另有一条比后置更硬的：`session.request_count == 0` —— **被测代码改不动的那个计数**。

### ③ 第一次真跑就抓到一条真的孤儿列，**而且是我们自己制造的**

```
gitops.test  ToDo -> 孤儿列 1 条：agenerp_gitops_probe
```

来源是 **P2.4 的 `verify-gitops.sh`**：清理时直接 `delete_custom_field`，
而 Frappe **不删物理列** ⇒ 每跑一轮就多积一条。

**一个自己制造孤儿列的验收脚本，没有资格验别人干不干净。**
⇒ 清理改走 `drop_orphan_columns`（自带收窄）。修完两个站点都回到零。

⚠️ 这条**不是判据抓的，是工具自己抓的** —— 它正是 P2.5 存在的理由。

## 顺带记一条踩到的

WBS 把验收路径写死为 `tests/tools/test_schema_drift.py`，而 `tests/unit/` 下已有同名文件。
`tests/` 没有 `__init__.py` ⇒ 同名 basename 让**整轮** pytest `import file mismatch`
（`tests/render/test_renderer.py` 模块头逐字记着这个坑）。
WBS 那条路径动不了 ⇒ 改另一个为 `test_schema_drift_oob.py`，**断言一条没动**。
