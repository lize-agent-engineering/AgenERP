## 1. Current Baseline（实读，2026-08-27 @ `7c8c303`）

### 1.1 仓内今天只有一个半前端

| 前端 | 状态 |
|---|---|
| **ERPNext Desk** | 跑着，全功能（`127.0.0.1:18080/app`）|
| **⌘K 侧边栏** `agenerp/serve/assets/desk.js` | 跑着 —— 但**它不是一个前端**，是**注入进 Desk 的一块**，429 行零构建 vanilla JS |
| **AgenERP Web（②③端）** | ❌ **不存在，只在架构图里** |

⇒ **本项是 ②③端的第一块砖。**

### 1.2 `agenerp/serve/` 的既有接缝

`app.py` 有三条路由：`/agenerp/health` · `/agenerp/explain` · `/agenerp/{asset}`。
资产路由**不认人、不接受路径参数**（`self.path` 只做等值比较），经 nginx
同源送进 Desk 页面。⇒ **加一个渲染器资产不需要新接缝。**

### 1.3 P2.1 已经把「判定」做完了，缺的是「画」

`agenerp/dsl/fallback.py::plan_render()` 已能回答「哪些块画得了、哪些落回、为什么」，
且有 9 条判据守着（含一条读源码确认无模型入口）。
**但「落回的那一块在屏幕上长什么样」不存在，「画得了的那一块怎么画」也不存在。**

### 1.4 路线 C 的立项依据（人 2026-08-27 选定）

`system-baseline.md` §3.2 逐字：Desk 覆盖 ~30 种 fieldtype、8 种视图、子表内联编辑、
报表引擎、打印格式、Client Script API；**重写必须 100% 完备**（漏一个 fieldtype
就有 DocType 打不开）；**Frappe 核心开发者本人的尝试（frappe-deskv3）已于 2022 年停止。**

⇒ 「统一在一个前端」若指「新前端覆盖全部功能」，是那条已被证明走不通的路。
**路线 C 把「100% 完备」的分母从「全部 DocType」换成「这个角色每天碰的那几个」** ——
分子不变，分母缩小到可达。**落回 Desk 的机制保留**（§4 兜底原则不动），
但**对目标角色的日常路径永不触发**。

### 1.5 🔴 目标角色已经在站点上，且权限是真的

`agenerp/seedusers.py:30-39`：角色 **「车间工人」**（`worker@hrd.example.com`），
**仅可读 3 个 DocType**：`Work Order` / `Stock Entry` / `Item`。
权限由站点上的 `Custom DocPerm` 强制，**不是我在 plan 里假设的**。

⚠️ 该文件还记着一条实测（2026-08-24）：**刻意不给 `DocType` 的读权限** ——
给工人发 `System Manager` 能让发现式候选集跑通，但那等于把「受限」这件事取消掉。
**本项不得为了让渲染器好做而放宽这个角色的权限。**

### 1.6 🔴 「100% 是多少」已经量出来了

对 3 个可读 DocType **及其 12 张子表**（共 15 张表 / **317 个字段**）统计 fieldtype，
与 `fallback.RENDERABLE_FIELDTYPES` 比对：

| 缺的类型 | 字段数 | 例 |
|---|---|---|
| `Table`（子表） | **12** | `Item.uoms` · `Item.barcodes` · `Work Order.required_items` |
| `Text Editor`（富文本） | **3** | `Item.description` · `Stock Entry Detail.description` |
| `Attach Image` | **2** | `Item.image` · `Work Order.image` |
| `Attach` | **1** | `Stock Entry Detail.image` |

**当前覆盖 299/317 = 94.3%。缺的只有 4 种类型、18 个字段。**

⇒ **路线 C 的可达性不是推测，是算出来的**：要补的是 4 种，不是 30 种。

### 1.7 ⚠️ 其中三种带安全代价，不能顺手补

`module-boundaries.md` §7.23 给 `desk.js` 写死的第 1 条硬约束逐字：

> **建 DOM 只走 `textContent` / `createTextNode` —— HTML 注入那一族 sink 在判据里是零命中。**

- **`Text Editor`** 的值是 HTML。渲染它 = 往 DOM 里塞 HTML = **直接违反这一条**。
- **`Attach` / `Attach Image`** 的值是一个 **用户可写字段** 里的 URL。
  当 `src` / `href` 用 = `javascript:` 那一族的入口。

⇒ **这三种的处置必须在 §2 里事先写死，并各自有判据。不许「先渲染出来再说」。**

## 2. 事先写死的判据与预测（预测在前）

### 2.1 🔴 主判据：目标角色日常视图的落回次数

**「日常视图」事先定义**（不许事后调）：三个视图，各自对应角色的一个日常动作 ——

| 视图 | 块 |
|---|---|
| `worker-work-orders` | `list`(Work Order) + `metric`(Work Order 计数) |
| `worker-stock-entries` | `list`(Stock Entry) + `detail`(Stock Entry 含其子表) |
| `worker-items` | `list`(Item) + `detail`(Item 含其子表) |

**R1（补类型之前）**：对这三个视图跑 `plan_render` → **落回次数 > 0**。
若为 0，说明我选的字段没碰到那 18 个缺口 ⇒ **视图定义不合格，重定，不是宣告胜利。**

**R2（补完之后）**：**落回次数 = 0。**

### 2.2 R3 · 补 `Text Editor` 不许引入 HTML 注入面

处置**事先定死**：**剥标签，只显示纯文本**，并在该字段旁给一个「在 Desk 中查看格式」的入口。
判据：渲染器源码里 `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write`
**零命中**（静态断言，与 `desk.js` 同族）。

⚠️ **这是一个取舍，照实记**：用户在新前端看不到富文本的格式。
**代价换的是「不引入一个注入面」，我认为值 —— 但这是我的判断，写在这里供人推翻。**

### 2.3 R4 · 补 `Attach` / `Attach Image` 不许引入 URL 注入面

处置事先定死：**scheme 白名单**，只放行 `/`（站内相对路径）与 `https:`。
其余一律不渲染成链接/图片，**降级为纯文本并说明原因**。
判据：喂 `javascript:alert(1)` / `data:text/html,...` / `vbscript:` 三种载荷，**必须不产出可点击元素**。

### 2.4 R5 · 权限由后端强制，前端只做提示

判据：以 **`worker@hrd.example.com` 的真实会话**跑活体判据，请求一个该角色**读不到**的
DocType（如 `Sales Order`）→ **后端拒**，前端显示「你看不到这个，因为…」，
**且前端从未自行放行过任何一条数据**。

⚠️ 这一条防的是「前端做判定」——`system-baseline.md` §4 逐字：
「权限由后端强制，前端只做呈现与提示」。

### 2.5 判定标准（事先写死）

| 组合 | 判定 |
|---|---|
| R1 ✅ 且 R2 ✅ 且 R3/R4/R5 全 ✅ | **路线 C 在这一个角色上成立**，本项过 |
| R2 ❌（仍有落回） | **不许改视图定义去凑** —— 照实报「还差哪几种」，本项不过 |
| R3 或 R4 ❌ | **停**。宁可落回 Desk，不可引入注入面 |

⚠️ **本项只证明「在车间工人这一个角色上成立」。** 不得推广到别的角色 ——
别的角色可读的 DocType 不同，缺的 fieldtype 也不同。**推广要另量。**

## 3. Decision · 渲染器用零构建 vanilla JS，不引入 frappe-ui

**选择**：沿用 `desk.js` 那条零构建接缝。

**理由**：
1. 路线 C 之后，覆盖面是 **4 种 fieldtype + 3 种块**，不是一个组件库量级的问题。
2. 仓内**没有任何前端构建链**（根目录无 `package.json`）。引入 npm + Vue 构建会牵动
   `tests/gates/test_zero_dep_boot.py`（P0 的「空环境变量下 `docker compose up` 全 healthy」），
   **而那条门禁在红线 1 内，我改不了。**
3. 判据形态可直接复用 `tests/ui/test_sidebar.py` 那一套（断言体受快门禁保护 + live 门禁重绑）。

**代价照实记**：与 WBS §5 字面「渲染器（**frappe-ui**）」偏离；长期组件复用不如组件库。

**残余风险与可逆性**：DSL（P2.1）与落回判定**都与 UI 库无关** ——
`plan_render()` 输出的是数据，换渲染实现不动它们。⇒ **这个决定是可逆的。**

⚠️ **这是我的判断，不是人裁定的。** 人 2026-08-27 选的是路线 C（覆盖范围），
**没有裁 UI 技术选型**。写在这里供推翻。
