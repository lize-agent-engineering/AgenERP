## 5. 设计

### D1 · 四步本体用 Python，`scripts/verify-gitops.sh` 是薄壳

**备选**：B 全写在 shell 里（照 WBS 字面）· C 全做成 pytest。

**否 B**：四步的断言都是「字段**真的**在/不在那个站点上」，shell 里那要靠 `grep` JSON，
脆且失败时说不清哪一步坏的；而 `apply_pack` / `SiteClient` 全在 Python 里。
薄壳照样满足「`verify-gitops.sh` 退 0」的字面。

**否 C**：GitOps 是**流程**不是单元；pytest 形态会诱使我把「建站」塞进 fixture，
那一步失败时长得像「测试跳过」——而一条会 skip 的判据等于一条不存在的判据。

### D2 · 只实现 `creates`，`updates` 继续显式抛

有调用方的只有 `creates`（第四步）。`updates` 今天仍然没有调用方 ⇒ **照 YAGNI 不做**，
且**保持显式抛而不是静默跳过**（P0.5 那条纪律不改）。
同一条 deferred 的重开条件对 `updates` 原样保留。

### D3 · 建字段**不放宽方向不变量**

`_assert_direction` 那条「建 = 只在包里」的不变量是接上真删除之后**挡住灾难性误删的最后一道闸**
（`apply.py:130` 逐字：不用裸 `assert`，因为 `python -O` 下它整条消失）。
实现 creates **不动它一行**。

### D4 · 探针用 `ToDo`，不用 `Item`

`gitops.test` 没有 erpnext ⇒ `Item` 在那边不存在。用 frappe core 的 `ToDo`。
⚠️ **代价**：与 P0.5 那条门禁（用 `Item`）不是同一张表，两者**互不替代**。

## 7. 🔴 实施中撞到的一条部署面事实 —— 第四步一度**假绿**

第一次跑完，①②③ 全过、第四步也报「gitops.test 上长出了字段」，
**只有最后那条「`frontend` 不受影响」红了**。查下去不是代码 bug：

```
经 nginx(18080)，Host=frontend     -> 有 Item DocType
经 nginx(18080)，Host=gitops.test  -> 有 Item DocType   ← gitops.test 上没装 erpnext，不该有
```

**nginx 的 `FRAPPE_SITE_NAME_HEADER=frontend` 把所有请求钉在 `frontend` 上**，
而 backend **没有对宿主发布端口** ⇒ 宿主上的 `apply_pack(site="gitops.test")`
在这套部署里**够不到第二个站点**，字段实际建在了 `frontend` 上。

⚠️ **那条隔离断言是唯一咬住它的东西。** 没有它，第四步会报成功 ——
一条「验了跨站点」的绿，而它连第二个站点都没碰到。
**这就是为什么两条前置断言（「本来没有」「那边也没有」）一条都不能省。**

**修法与被否掉的修法**（人 2026-08-28 裁定加端口）：

| | |
|---|---|
| ❌ 改 `FRAPPE_SITE_NAME_HEADER=$host` | 浏览器判据打的是 `127.0.0.1:18080`，Host 就是 `127.0.0.1`，Frappe 会去找一个叫 `127.0.0.1` 的站点 —— `agenerp/site.py` 模块头记着的正是这个坑 |
| ✅ 给 backend 加一格**只绑环回**的端口 | gunicorn 自己按 Host 正确分站。现有判据全走 18080，不受影响 |

核过不冲突：`test_explain_same_origin.py` ① 守的是 **`agenerp-serve`** 不发布端口（不是 backend），
`test_published_ports_bind_loopback_literally` 要求字面绑 `127.0.0.1` —— 新增那格满足。
改完实测：`tests/unit/test_explain_same_origin.py` **23 passed** ·
`pytest -m live tests/render` **18 passed**（浏览器那条没被带坏）。
