### 1.2 🔴 不能塞进 `READONLY_CONTRACTS` —— 那会撞红线

`tests/tools/test_live_conformance.py` **是门禁断言体**
（被 `tests/gates/test_tool_execution_live.py:57` 按路径加载），红线①内、**只能由人改**。

## 2. 设计

### D1 · 自己的契约族 `INSPECTION_CONTRACTS`，`READONLY_CONTRACTS` 一个字不动

```
READONLY_CONTRACTS   十个，**模型面**（tool_schemas() 按它生成）—— 不动
INSPECTION_CONTRACTS 巡检面，schema.drift 在这里 —— 不进模型工具面**由构造保证**
ALL_CONTRACTS        两者之和，`get()` / `contract_of` 按它解析
```

⇒ `execute("schema.drift", …)` 照走前置/裁剪/后置整层（满足 `tests/tools/` 那条验收），
而模型永远看不见它 —— **不需要排除表**。

⚠️ `tests/tools/test_registry_pairing.py` 那条 `len(READONLY_CONTRACTS) == len(EXECUTORS)`
要改成按 `ALL_CONTRACTS` 配对（**它不是门禁断言体**，已核）。配对这条不变量本身不放松。

### D2 · 两个入口：单表 + 按**包管辖面**批量

- `doctype=<名>` —— 查一张表
- `pack=<包路径>` —— 扫 `pack_doctypes(pack)` 那一组

**二选一，都不给或都给一律拒**（`ToolError`）。批量的范围由**包**定，与 P2.4
「包是唯一真相源」同一条线 —— 而不是「扫全站 1000+ 表」那种既慢又没人负责的口径。

### D3 · 返回 `{doctype, column}` 行，不是裸列名

裸列名在批量模式下说不清是哪张表的。`must_keep=("doctype","column")` 写进契约。

## 4. 🔴 实施中的两条

### ① basename 撞车 —— 整轮 pytest `import file mismatch`

WBS 把验收路径写死为 `tests/tools/test_schema_drift.py`，而 `tests/unit/` 下**已经有**
一个同名文件。`tests/` 没有 `__init__.py` ⇒ 同名 basename 让**整轮** pytest 收集失败
（这个坑 `tests/render/test_renderer.py` 模块头逐字记着）。
⇒ WBS 那条路径动不了，改另一个：`tests/unit/test_schema_drift.py`
→ **`test_schema_drift_oob.py`**，**断言一条没动**，模块头写明改名理由与两者分工
（那边验**口径**，这边验**工具面**）。

### ② 巡检第一次真跑就抓到一条真的孤儿列 —— **而且是我自己制造的**

```
gitops.test ToDo -> 孤儿列 1 条：agenerp_gitops_probe
```

来源是 **P2.4 的 `verify-gitops.sh`**：它清理时直接 `delete_custom_field`，
而 Frappe **不删物理列** ⇒ 每跑一轮就多积一条。
**一个自己制造孤儿列的验收脚本，没有资格验别人干不干净。**
⇒ 清理改成走 `drop_orphan_columns`（自带收窄：只碰本次删掉的 ∩ Frappe 判定的孤儿列，
历轮残留别人家的列一个都不碰）。修完实测两个站点都回到零。

⚠️ 这条**不是判据抓的，是工具自己抓的** —— 它正是 P2.5 存在的理由。
