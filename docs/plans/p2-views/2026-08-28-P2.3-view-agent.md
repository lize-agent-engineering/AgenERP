## 2. Goals / Non-Goals

### Goals

1. 一个自然语言 → `View` 的控制循环，**校验由循环无条件执行，模型没有绕过它的路**。
2. 两条 fail-closed 各有判据：修复轮用尽**不产出视图**（不降级交付）· 拿不到 schema **不算过**。
3. 三层判据落地：离线本体（零 token）· live 端到端（draft 位置）· 量化评测（开发期模型）。
4. 量化评测的**期望集合本身有判据守着真实性** —— 否则测的是「我编得对不对」。

- 不动 `agenerp/explain/` 与 `agenerp/dsl/` 任何一行

## 5. 设计决策（每条带备选与残余风险）

### D1 · 新写 `agenerp/views/loop.py`，复用零件**不复用** `ExplainLoop` 本体

**备选**：B 复用 `ExplainLoop` 并把证据门禁参数化 · C 抽公共基类给两个 Agent。

**否掉 B 的理由是硬的**：视图 Agent 的停止条件是「DSL 合不合法」，解释 Agent 的是
「证据够不够」。塞进 `ExplainLoop` 只有一条实现路径 —— 在证据充分性门禁上开一个
`if task_class == "view": skip`。**那就是给 P1.4 那道门禁开后门**，而它正是
P1.0 入口关口实验证明「门禁能补偿模型能力」的那个东西。

**否掉 C**：过早抽象，且要动 P1.4 已过判据的代码。

**残余风险**：两个循环会有重复逻辑（工具回注、clip、记账）。**现在不抽** ——
第三个 Agent（P3 操作 Agent）出现时再评估，那时才有三个样本判什么是真共性。

### D2 · `dsl.validate` / `dsl.preview` **不进模型可见工具面**（人 2026-08-28 裁定）

**与 owner doc 字面偏离**：`agents-and-roles.md` §5.1 第 119 行把这两个列为视图 Agent 的工具。

**理由**：D-15「规则能覆盖的流程不 Agent 化」。「这个视图合不合法」「哪块画不了、为什么」
`validate()` 与 `plan_render()` 纯规则零模型就能答。本仓已有同形先例：`permission.scope`
**刻意不进模型工具面**，因为开场注入已把那一步确定性化（`explain/loop.py` 模块头逐字写着理由）。

**备选**：都进（照字面）· 只开 `preview`。都会留下同一个缺口 ——
**模型可以不调就交**，除非再叠一层强制，那就变成重复校验。

**残余风险**：与 owner doc 字面不一致。**本决策可逆**（加两份契约 + 注册表项即可），
且 owner doc 的更新在收口清单里。

### D3–D5 · 判据分层 / 双层判分 / 评测域（人 2026-08-28 裁定，三条）

- **D3 判据分层**：离线本体（WBS 那条命令打它）+ live 门禁 + 量化评测，**三者判的不是同一件事**
- **D4 双层判分**：确定性硬判把门 + 判官只答「切题吗」
- **D5 评测域**：主集在车间工人域（含「落回 = 0」）+ 域外子集（只判 validate 过 + 落回有理由），
  **两个数分开报，不合并成一个总成功率**

### D6 · 开发期模型走 `claude -p`，产品 `routing` 一行不动；**P2.3 以开发期数字判过**

`routing/config.py` 按 `model-management.md` §12.1 ① **不许出现厂商名与端点**
⇒ Claude 这条路只能是 `tools/experiments/p2_view_agent/` 侧的适配器，与
`tools/experiments/p1_entry_gate/llm.py` 同族（模块头逐字「实验设施，不是产品代码」）。

**残余风险（照实记，不许被写成结论）**：这样拿到的数字**与 P2.0R 那 57/60 = 95.0% 不可比**，
也**不代表百炼上任何模型的表现**。凡引用本项数字处必须点名模型。
重开条件写在「Deferred But Adjudicated」。

### D7 · live 端到端先写在 `tests/agents/`，**不落 `tests/gates/`**（人 2026-08-28 裁定）

`tests/gates/**` 是红线 ②，改动要人明说指派 + `Gates-Change-Approved-By:`。

**残余风险**：交接文档 §3⑤ ——「**在最终位置跑一遍**」和「跑过」是两件事，
门禁在草稿位置 5 passed、落进 `tests/gates/` 后一格跑不了。
⇒ 将来落地 gates 时**必须在最终位置重跑**，本项不预支那句话。

### D8 · `REPAIR_ROUNDS` v0 = **3**，且这个数**现在没有实测依据**

**照 §1.6 的纪律：本仓的每个上限都要有出处。** 这个数今天没有 ——
`MAX_TURNS` 由 25→40 是实测换来的，`RESULT_CHARS` 由 6000→20000 也是。
`REPAIR_ROUNDS` 只是「先取一个最小可观测值」，**它是待测量，不是结论**。

**Phase 4 跑完必须回答一个问题**：有没有题目卡在修复轮上限上？
有 ⇒ 按实测调整并记 D-16（本项目的结论以本项目实测为准）；
没有 ⇒ 把「N 条题里最深修复轮数 = k」写进收口，这个数才算有出处。

⚠️ **不许在没跑之前把它调大** —— 那就是 §3② 那条「自己的闸停的，却记成能力问题」的反面：
先把闸放到看不见，同样量不出真实形状。

## 6. 模块边界（结构定义，不是实现细节）

```
agenerp/views/
  wire.py    线格式 ↔ View。**只解析形状，不判对错**
  loop.py    控制循环 + ViewProposal
```

**`wire.py` 的纪律照 `blocks.py`**：解析器要能造出**非法**的 `View`，否则校验器的拒绝路径
根本没法测。`WireError` 与 `DslError` **分开**——「模型交的不是 DSL」和「模型交的是错的 DSL」
回注话术不同，混成一个就分不清是格式没说清还是字段找错了。

**`loop.py` 的接缝**照 `ExplainLoop.__init__`：`adapter` / `client` / `executors` 都是注入位。

**`RESULT_CHARS` 复用 explain 那个 20000，不自己再定一个**（§1.6）。

### 循环形状

```
开场注入（可见范围，规则面，不靠模型想起来调）
  → 模型选工具：schema.search / meta.fields / system.overview   ← 只有这三个
  → execute → 回注（clip 20000）
  → 模型交 DSL JSON
  → 🔴 循环无条件跑 wire → validate → plan_render               ← 模型没有绕过它的路
  → 不过：错误逐条回注，强制重来（上限 REPAIR_ROUNDS）
  → 过：出 ViewProposal
```

**不给数据工具**（`query.read` / `doc.get`）：视图 Agent 要的是 schema 不是数据行。
给了它只会去查数据、烧 token，而答案不在那儿。

### 两条 fail-closed，形状不同，都要写死

1. **修复轮用尽仍不合法 ⇒ 不产出视图**（`view is None` + `stop_reason`）。
   **不许把画不了的块删掉再交** —— 那正是 `fallback.py` 模块头点名的坏选择
   （静默丢弃，用户以为那块内容本来就不存在）。
2. **拿不到 schema ⇒ `SchemaUnavailable` 冒上来，不吞。**

### ⚠️ 「落回 Desk」不是失败

块粒度落回照常交付、理由随件（P2.2 已定的正确行为）。
**评测主集要求「落回 = 0」是评测的判据，不是循环的判据** —— 两件事必须分开写死，
否则循环会长出「为了不落回而删块」的动机。
