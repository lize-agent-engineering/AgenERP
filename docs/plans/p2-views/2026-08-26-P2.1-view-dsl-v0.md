## 1. Current Baseline（实读，2026-08-26 @ `f6073b1`）

### 1.1 仓内今天没有任何 DSL

`agenerp/` 下无 `dsl` 模块，`tests/` 下无 `dsl` 目录（`ls` 确认）。**这一项是净新增。**

### 1.2 可以照抄的既有形状：`agenerp/contracts.py`

契约层已经把「**声明格式 + 校验器 + 封闭取值**」这套做过一遍，且约束很硬：

- **纯 Python 声明，不用 YAML** —— 理由写在它的模块 docstring 里：
  CI 的 `gates-l1` 只 `pip install pytest`，`import yaml` 会红在缺依赖上
- **取值封闭**（`RISK_LEVELS` / `OPERATORS` 之类的元组），不是自由字符串
- **校验器对注入进来的数据结构求值，本层不连任何站点** ——
  这正是「可独立测试」得以成立的机制

⇒ **视图 DSL 照这个形状做**，不发明第二套风格。

### 1.3 P2.0 已经定死了载体

**视图产物落 AgenERP 自有表，不落标准 `Workspace`**（P2.0 实测：Workspace 会被升级
整条删了重插，只有 `is_hidden` 幸存）。⇒ DSL **不得**被设计成 Workspace fixture 的形状。

### 1.4 三条硬约束在本项上的具体含义

| 约束 | 在 P2.1 上是什么 |
|---|---|
| ① 判据不许只验「调得通」 | **「DSL 校验过 ≠ 字段真的存在」** —— 结构合法但指向一个不存在的字段，**必须被拒**；且必须有变异证明这一层真的有牙 |
| ③ 规则能覆盖的不 Agent 化（D-15） | 校验、以及「未支持一律落回 Desk」的判定，**全是规则面，不许交给模型判** |
| ④ 产出必须指回真实存在的字段 | 校验器的第二层就是这条约束的执行体 |

## 2. 设计（只写接口契约，不写实现细节 —— 指南第 6 条）

### 2.1 五种块，取值封闭

`list` · `detail` · `metric` · `chart` · `explain`（§10.2 原样，不增不减）。
**块类型是封闭元组**，不认识的一律不是「宽容地忽略」，而是走 §2.3。

### 2.2 校验器**必须分两层**，且第二层不可跳过

| 层 | 验什么 | 依赖 |
|---|---|---|
| **L1 结构** | 块类型在封闭集内 · 必填段齐 · 取值在枚举内 · 引用形状是 `DocType.fieldname` | **零依赖，离线** |
| **L2 字段存在性** | 每一个被引用的 `DocType.fieldname` **在给定的 schema 视图里真的存在** | 对**注入的** schema 求值，**本层不连站点** |

🔴 **`validate()` 不接受「只跑 L1」这种调用方式。** 没有 schema 视图就没法验字段，
那时它**必须报「无法验证」而不是「通过」** —— 这正是 P1 那个 `or` 的教训：
**验不了的东西不许算过。**

### 2.3 「未支持一律落回 Desk」是 fail-closed 的规则面判定

- 不认识的块类型 → **落回 Desk**（不是报错炸掉，也不是静默丢弃）
- 认识块但字段类型不在渲染器支持集内 → **该块落回 Desk**
- **判定完全由封闭表驱动**，不含任何模型调用（D-15）
- 落回时**必须带原因**（哪个块、哪个字段、为什么）—— §10.3
  「前端权限只做提示（『你看不到这个，因为…』）」是同一条纪律
