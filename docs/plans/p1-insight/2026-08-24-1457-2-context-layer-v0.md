## 5. Infrastructure And Config Prereqs

### 5.1 前置

- **本批第一个 plan（P1.1 模型路由 v0）必须先 `completed`**。理由：会话记录要记每一轮的
  token 三项用量（`missions/p1-insight.json` `_notes.p1_specific` ②），
  那个形状由 `agenerp/routing` 的 `Usage` 定义。先写会话再改形状等于返工。
- 不需要活站点、不需要 docker、不需要 LLM 凭据。**本 plan 全部判据零网络**。

### 5.2 `Decision` 前置 —— 「会话落 DocType」在 v0 落成什么

**选定（B）：端口 + 零依赖内置实现 + DocType 声明作为 git 产物；活站点建表交人。**

三条备选与否决理由：

| 方案 | 否决/选定理由 |
|---|---|
| (A) 直接在活站点建 DocType 并写记录 | **否决**。风险档 L3 强制人批（§1.4），loop 自行执行等于绕过人批；且 `SiteClient` 侧无 teardown，回滚只能手工 |
| **(B) 存储端口 + 零依赖内置实现 + DocType 声明落 git，建表交人** | **选定**。WBS 的验收原文是 `pytest tests/context -q` 退 0，(B) 完整满足；§8.5 逐字要求「**内置实现必须存在且零外部依赖**」，(B) 正是它；声明落 git 满足 L3 的「落 git + 可回滚」两项中 loop 能做的那部分 |
| (C) 只做内存实现，不出声明 | **否决**。那样「落 DocType」四个字一点没兑现，收口时只能靠措辞含糊过关 |

**可逆性声明（Protected Areas 最后一行的 Required Evidence，逐字回答）**：
本 plan **不新增任何对活站点的写调用**——`agenerp/context/**` 不 import
`SiteClient.create_doc` / `ensure_doc`，Phase 3 有一条判据专门断言这一点。
因此**站点侧回滚问题在本 plan 的交付面上不产生**。
将来人手工建表后要回滚，手工命令原文为
`docker compose exec -T backend bench --site frontend backup`（先备份）+ 在 Desk 里删除该 DocType；
**这一条照实写进 STATE §3 的 needs-human 行，不写成「已提供回滚」。**

### 5.3 判定面缺口（同 §1.6）

三条代偿控制，全部在本 plan 权限内：① Phase 3 的假实现变异自查；② 独立关闭审计；
③ 收口时**在 STATE §3 追加**一条 needs-human（`tests/context` / `tests/routing` / `tests/tools`
一并接进 `unit-and-contracts` / `lint`，外加本 plan 的建表批准）。
**收口时不得声称 CI 已覆盖 `tests/context`。**

### Phase 1 — ① 即时上下文的确定性装配

Status: planned

Skill: `none`

- Item Types: `Add | Proof | Decision`
- Prereqs: §5.1（P1.1 完成）

- [ ] `Add` — `ImmediateContext`：当前单据（`doctype` + `name` + 完整字段）、角色、视图三项，
      由调用方给，**装配面不自己去猜**。装配产物是一个可断言的结构，不是一段拼好的字符串
      ——字符串没法断言「哪个字段被裁掉了」。
- [ ] `Add` — 裁剪策略：实现 §8.2 的四条优先级规则中**本 plan 范围内的两条**
      （① 当前单据完整字段不可裁剪；② 已执行动作的审计记录不可压缩）。
      另两条（记忆排序、schema 相关度）分别属 ③/④ 层，Non-Goals 1/2，**装配面留位不实现**，
      留位方式写进落点节。
- [ ] `Decision` — **自由文本边界标记在本层要不要再包一次**。
      `agenerp/tools/runtime.py` 的 `wrap_free_text` 已在**工具执行入口**这一个咽喉上包过
      （`module-boundaries.md` §7.5 落点）。而 ① 层的「当前单据完整字段」是**前端注入**的，
      **不经过工具执行入口**——这是一条 §7.5 今天没有覆盖到的新入口。
      默认取「包」，理由是 §7.5 的红线逐字是「任何来自工具结果的文本」，
      而前端注入的单据字段同样是用户可写自由文本，攻击面同源（Spike 01 探针 5 的场景正是
      工人写 `resolution` 字段、老板提问时读到）。
      备选是「不包，靠前端保证」——否决理由：前端不在本仓，靠不住的东西不能当结构性防御。
      **残余风险**：包两次的字段会出现嵌套标记，需在实现里定一次「已包过就不再包」的判据。
      裁定写进 `module-boundaries.md` 新增落点节。
- [ ] `Proof` — `tests/context/test_immediate.py`（unit，零网络）：
      ① 当前单据字段**一个都不许被裁**（构造一个超长单据，断言字段集合恒等）；
      ② 自由文本按 `Decision` 的裁定被包裹，且**不重复包裹**；
      ③ **反测**：把「不可裁剪」改成「超长就截断」，必须有测试红。

1. **`Session` 同名不同义造成误读**（§1.1）。缓解：产品类名带 `Conversation` 前缀，

   收口时必须照实说，不得声称 WBS §4 P1.2 之外的任何东西。

   **残余**：判据认的是标记串字面，注入方若写出与标记串等价的变体仍可能钻过去——
   这继承 P1.0a 的 `wrap_free_text` 既有残余风险，本 plan 不宣称消除它。

5. **P1.1 未完成时开工。** 缓解：§5.1 写死为 Prereqs。
