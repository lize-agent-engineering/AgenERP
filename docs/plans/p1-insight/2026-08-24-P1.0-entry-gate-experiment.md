## 0. 这个实验要回答什么

**承重命题**：*确定性的循环门禁，能否补偿模型能力的不足？*

它承重在于：若成立，本项目可以用**便宜模型 + 强门禁**跑；若不成立，成本模型
与 P1.7「单次解释成本上限」的整个设计都要重估。

**不回答**：门禁能补偿多少、对哪些模型成立、对哪类问题成立。
⚠️ **不得据此宣称任何未实测的推广结论。**

## 1. Current Baseline（全部实读，2026-08-24）

### 1.1 门禁已有两条，L3 不存在

`agenerp/tools_readonly.py` 里 `EVIDENCE_GATE` 是两条声明式 Condition：

```
L1  问题点名了某张单据 → 接受 answer 之前，必须已对它调用过 doc.links
L2  doc.links 查出的已提交下游单据 → 必须逐张 doc.get 之后才能作答
```

**L3（两跳传递闭包）尚未定义**，是本实验要设计并验证的东西。

### 1.2 ⚠️ 规则的出处已随 D-9 失效，必须重述

`docs/design/agents-and-roles.md` §5.0 ① 逐字写着：

> 那 10 米是 `LOSS-00003` 已审批的合理损耗，补发是错误操作。

`LOSS-00003` 是 XM 自建的 custom DocType，**已按 D-9 退役**。规则 L1/L2 本身
仍然成立（它们不依赖那张表），但**推出它们的那个案例已不存在**，且新数据集
的陷阱形状不同。本 plan 的第一项任务就是重述这一节。

### 1.3 新数据集的陷阱形状（实读，与旧案例**不同**）

| | 旧（XM，文档现状） | 新（恒锐动力，实测） |
|---|---|---|
| 少发的部分怎么解释 | 有 `LOSS-00003` 记「已审批损耗」 | **没有任何解释文档**——订单被人工 `Closed` |
| 漏看的形态 | 没打开那张单 | 那张单不存在，字段就在订单上 |
| 真正的坑 | 少看一层血缘 | **一整批产出从订单侧不可见** |

### 1.4 决定性事实：外协批是**孤儿**

活站点实读（`frontend` @ 2026-08-24）：

```sql
-- 指向 SAL-ORD-2026-00001 的东西，全站只有一条
Delivery Note Item   1     ← 只有发货单
Sales Invoice Item   0
Work Order           0     ← 工单的 sales_order 是 NULL
```

且 **`Subcontracting Order` 在 ERPNext v15 里根本没有 `sales_order` 字段**——
外协批结构上就无法挂回销售订单。

于是从订单出发做 `doc.links`，**只能看到那一张发货单**。两批共 2,000 台的
产出，从订单侧完全不可见。

### 1.5 由此得到的正确答案与两种错法

**正确答案（需要归因，不只是报数）**：

> 成品仓 1,010 台 = 入库 2,000（自制工单 1,000 + 外协收货 1,000）− 发货 990。
> 根因是**为同一张 1,000 台的订单做了两批生产**；账面全绿是因为订单被人工
> 置为 `Closed`，系统据此按完成计（达成率 100%），而实发仅 990 台。

**错法 A（一跳，订单侧）**：订单 → 发货单 → 「订 1,000 发 990，少发 10 台」。
每个数字都对，**漏掉 1,000 台**，且完全没提积压。

**错法 B（半跳，只看 Bin）**：「成品仓有 1,010 台」——报了数，**没有归因**，
等于没回答「为什么」。

### 1.6 ⚠️ 新发现的离线/站点分歧（本 plan 顺带处置）

离线数据集里工单挂着 `sales_order = SAL-ORD-2026-00001`，**站点上是 NULL**
（装载器未送该字段）。D-12 新加的 `_document_graph_checks` 只比**条数**，
比不到**字段**，故未抓到。

> **这不是本实验的噪声，而是它的一部分**：实验必须跑在站点上（Agent 读站点），
> 而站点上「工单挂不挂订单」直接决定 `doc.links` 的返回。
> 处置见 §4 任务 T0。

## 2. 事先写死的假设（CP9 继承项 ②：预测在前、结果在后、逐条吻合）

**以下四条在跑之前逐字写死。跑完逐条对照，不许事后改写。**

### H1 · 无门禁 + 弱模型 → 错法 A 或 B
`qwen-plus`（外部基准 75.0%）在**无门禁**配置下回答该问题，将给出错法 A 或
错法 B，**不会**自发地从 Bin 反查入库来源。

### H2 · 有门禁 + 弱模型 → 正确答案
同一个 `qwen-plus`，在 **L1+L2+L3 门禁**下被强制续跑后，将给出 §1.5 的正确
答案（含「两批生产」这一根因）。

### H3 · 无门禁 + 强模型 → 结果不确定，**这一格才是真正的看点**
`qwen3.6-plus`（84.1%）在**无门禁**下的表现事先不预测。
- 若它自发答对 → **H1 的失败模式与模型能力有关，而非与门禁有关**，
  「门禁补偿能力」这个命题被削弱：更强的模型可能不需要门禁。
- 若它也答错 → 命题被加强：这是**结构性**的证据不足，不是能力问题。

### H4 · 门禁的代价可测且有上限
有门禁配置的工具调用次数将高于无门禁配置，但**不超过 3 倍**。
（依据：Spike 02 实测补上 `permission.scope` 后调用从 35 次降到 1 次——
门禁的方向是**收敛**而非发散；若这里出现发散，说明 L3 的设计有问题。）

### 判定标准（同样事先写死）

一次回答记为 **正确**，当且仅当**同时**满足：

1. 报出 1,010 台这个数
2. 指出入库 2,000 与发货 990 的差额构成
3. **点名两批生产中的至少一批是多余的**（即触及根因，而非只描述现象）

只满足 1、2 记为 **不完全**；给出错法 A 记为 **错误**。

## 3. Goals

1. 设计并实现 **L3（两跳传递闭包）** 门禁规则，形态与 L1/L2 一致（声明式 Condition）
2. 搭一个**最小控制循环**：10 个只读工具 + 可开关的门禁 + 强制续跑消息
3. 跑满 **2×2 网格**（门禁开/关 × 弱/强模型），每格 **3 次**共 12 次

## 5. Task Route

### T0 · 先把站点与离线的字段分歧处置掉（前置）
工单的 `sales_order` 在站点上是 NULL。**两条路，需在跑实验前定**：

- **(a) 补上链接**：装载器送 `sales_order`，则 `doc.links` 从订单能看到工单，
  陷阱变成「看得到自制批、看不到外协批」——**仍是两跳，但更贴近真实误读**
- **(b) 保持 NULL**：陷阱是「两批都看不见」，更极端

⚠️ **这个选择直接改变实验难度，必须在写死假设之后、跑之前定，且记录理由。**
本 plan 建议 **(a)**：它更贴近真实 ERP（工单通常挂订单），且让「外协是孤儿」
这一条成为**唯一**的不可见项，实验因此测的是一件事而不是两件。

顺带：给 `_document_graph_checks` 补一层**关键 Link 字段**对账，使这类字段级
分歧不能再无声发生。

### T1 · 定义 L3
形态与 L1/L2 一致，落在 `agenerp/tools_readonly.py`：

```
L3  作答涉及某个仓库的库存数量 → 必须已对该库存的入库来源逐个 doc.get，
    且来源集合覆盖 Stock Ledger 里全部正数流水的凭证
```

**判据**：L3 必须能挡住错法 A。写一条单测，喂一段「只查了发货单就作答」的
轨迹，断言 L3 判违规。

### T2 · 最小控制循环
`tools/experiments/p1-entry-gate/`（**不进 `agenerp/`**，这是实验设施不是产品）：
- 输入：问题、模型名、`--gate on|off`
- 循环：模型选工具 → 执行 → 回注结果 → 模型作答 → **门禁判定** → 违规则回注
  强制续跑消息并继续
- 输出：结构化轨迹（工具调用序列 + 最终答案 + 门禁判定记录 + token 用量）

### T3 · 跑 2×2 网格
每格 3 次，共 12 次。**提示词四格逐字相同**。轨迹全部落盘存证。

### T4 · 判定与落账
逐条对照 H1–H4。**H3 那一格若与预期相反，必须照实写并重估命题**，不许
挑选性叙述。

## 6. 已知风险（事先登记）

**① 强模型可能让实验失效。** 若 `qwen3.6-plus` 无门禁也答对（H3 的前一支），
则该格证伪不了任何东西——那正是要靠**弱模型格**承重的原因，也是为什么
必须跑满 2×2 而不是只跑强模型。

**② 单题实验的外推性极弱。** 一道题、12 次运行，只能得出「在这道题上」的
结论。**任何"门禁能补偿模型能力"的一般化表述都是超纲的。**

**③ 门禁可能过拟合到这道题。** L3 是照着这个陷阱设计的，天然对它有效。
**缓解**：L3 的措辞必须是**通用的**（"库存数量 → 入库来源全覆盖"），不许
出现 `SAL-ORD-2026-00001` 之类的具体单号；并在 T1 用一条与本题无关的合成
轨迹反测。

**④ 成本。** `qwen3.6-plus` 是推理模型（实测回两个字烧 195 reasoning token）。
12 次运行 × 多轮工具调用，需在 T2 里加**单次运行 token 上限**并记账。
