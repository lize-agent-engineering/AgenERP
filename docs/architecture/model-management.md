## 12. 模型管理

### 12.1 三条原则

**① 默认不指向任何商业 API。**
开源项目不能强制用户购买 token。默认支持任意 **OpenAI-compatible endpoint**（DeepSeek / vLLM / Ollama / 主流国产均兼容）。DeepSeek 是推荐配置，不是依赖。

**② 按任务与风险路由。**

| 任务 | 模型档位 |
|---|---|
| 形态生成、跨职能规划 | 强模型（如 DeepSeek-V4-Pro） |
| 解释、查询、视图生成 | 快模型（如 DeepSeek-V4-Flash） |
| 图像 embedding | 独立通道（现为 Cohere embed-v4.0） |

**③ 能力声明与校验。**
每个 Agent 声明所需最低模型能力（工具调用 / 长上下文 / 推理强度）。换模型时校验，**不满足则明确失败，绝不静默降级**。

### 12.2 成本：前缀缓存是可行性前提，不是优化项

Spike 02 实测（`claude:sonnet`，四道探针的通过态）：

| 探针 | 工具调用 | in tok | out tok | USD |
|---|---|---|---|---|
| 正确性（带门禁） | 5 | 47,794 | 6,936 | 0.339 |
| 诚实性 | 4 | 38,713 | 3,316 | 0.251 |
| 越权边界 | 1 | 6,119 | 1,254 | 0.043 |
| 幻觉压力 | 7 | 50,952 | 7,914 | 0.375 |

**平均 $0.252/次提问**，约合 ¥1.8。20 人每天各问 10 次 ≈ **$1,500/月**——中小企业不可接受。

这是**最坏条件**下的数字：每轮重发全部对话，`p4` 的 50,952 input token 里绝大部分是重复前缀。
但它说明了一件事：

> **没有前缀缓存，解释 Agent 在经济上不成立。**
> 系统指令、工具定义、DocType schema 构成的稳定前缀不是「可以顺便缓存一下」，
> 而是这条产品线能否存在的前提。

→ 因此：

- **P1 的验收标准必须包含单次解释的成本上限**，与正确率并列
- 按租户/角色设 token 预算与配额
- L0 只读任务优先走快模型
- **本地模型是成本的另一个答案**：`qwen3:14b` 全程 $0（见 §12.3）

### 12.3 本地模型：能跑，但有能力落差（Spike 03 实测）

§12.1 ①「默认不指向任何商业 API」在**技术上成立，在能力上有代价**。同一个受约束循环、
同一套工具、同一批探针，换成本地 `qwen3:14b`（Ollama，笔记本）：

| 探针 | claude:sonnet | ollama:qwen3:14b |
|---|---|---|
| 越权边界 | ✅ 1 次调用 | ✅ 2 次调用 |
| 诚实性 | ✅ 4 次调用 | ⚠️ 通过，但误称自己无权读 Quotation（实际有权） |
| 正确性（多跳） | ✅ 5 次调用 | ❌ 追了血缘但没打开关键单据 |
| 幻觉压力 | ✅ 7 次调用 | ❌ ①② 均答「无法确定」，但**未编造** |

三条结论：

1. **JSON 动作协议在本地小模型上稳定**——全程解析成功，未触发协议重试。
   这支持「连原生 tool-calling 都不必要求」，model adapter 可换是真的
2. **诚实性不随模型变弱而丢失**。qwen 答不出时说答不出，没有编造数字。
   这很关键：**弱模型的失败模式是「答不全」，不是「编瞎话」**——前者可接受，后者不可
3. **多跳推理是能力分水岭**。单跳查询与权限判断本地模型够用；跨单据追溯不够

→ **能力声明与校验（§12.1 ③）必须按任务分档，不能全局一刀切**：

| 任务 | 最低模型能力 |
|---|---|
| 权限判断、单跳查询、状态解释 | 本地 14B 级可用 |
| 跨单据血缘推理、根因诊断 | 需强模型，或**由更强的循环门禁补偿**（见 §5.0 ①） |
| 形态生成、跨职能规划 | 强模型 |

### 12.4 数据出境

中小企业订单、客户、成本数据发往云 API 是常见的合规阻碍。
→ **首版就必须能配本地模型**，哪怕效果降一档。model adapter 可换不是「以后再说」，是架构底线。
