## 1. AGE / mission-driver → **续用**（条件见下）

### 1.1 判据一：≥1 个工作项完整由循环推完 → ✅

**满足，且不止一个。** 最完整的一例是**工作项 10b**（`P1.8a-fix`）：

| 环节 | 证据 |
|---|---|
| drafted | `2026-08-25-1118-1-gates-l2-live-intermittent-red.md`，经 5 轮独立评审 |
| executed | Phase 1–3 全走完，产出机制陈述 + 离线判据 + 7 个变异 |
| 门禁绿 | 三次连绿 `182ef2a` / `cb3ad79` / `aae1843`，run id 逐个可查 |
| 关闭 | 独立收口审计（审计员非本轮执行者）判 `issues` → 人答绑定 2 → 收口 |

**这一例里循环做了三件人侧没做的事**：
① 机制陈述**每个成分都指回一个数字**，并自己点明「为什么某次落到 30 秒之外**未查明**」——**没有拿说得通的故事填洞**
② 给人侧的修复**补了 7 个变异**证明判据有牙（人侧只跑了「现在是绿的」）
③ 收口前**验了解锁提交的 author 是人不是自己**——防的是自行消解约束自己的条款

### 1.2 判据二：门禁误放行次数 = 0 → ❌ **未满足，发生了 1 次**

**形态**：`test_the_user_in_the_answer_is_the_person_the_real_sid_resolves_to` 里
`assert payload["answer"] or payload["accepted"] is False` —— 一个 `or`，
模型拒绝时 `accepted` 恰好就是 `False` ⇒ **空答案照过**。

**实际后果**：CI 的路由器走到一个没有免费额度的模型 ⇒ 每一次解释都 403 ⇒
每一次回空答案，而这条判据**一路绿着数日**。那阵子报的「54 项全绿」，
在「Agent 到底能不能答」这一维上**是空的**。

**它不是被任何判据发现的** —— 是人侧手动跑了一次真解释才撞出来的。

### 1.3 那为什么判「续用」而不是「停用」

停用条件逐字是「**出现门禁误放行 ≥1 次<u>且根因在引擎</u>**」。两个条件都要成立。

**误放行成立。根因在不在引擎，逐层拆开看：**

| 层 | 这一层做了什么 | 是不是引擎 |
|---|---|---|
| 那条弱断言 | 写它的是 `18dc465`（`Agent Developer`，**不是人侧**）| 是**执行产物**，不是引擎 |
| 独立收口审计 | 核了「plan 说要做的做了没」，**没问「这条判据验的是不是它名字说的那件事」** | **这一层是引擎的** |
| 判定器 | 数红绿，按设计它不读断言语义 | 按设计工作 |

⇒ **引擎的既有步骤都按设计工作了；缺的是一个「问判据本身」的步骤。**
那是**设计缺一环，不是引擎失灵** —— 区别在于：前者补一环就好，后者要换。

**佐证**：同一个引擎在本阶段**三次先于人侧发现问题**（见第 3 节），
它的收口纪律是有效的，只是纪律的**覆盖面**漏了「判据自身」。
这一环已由 §7.2.1 补上（本次复盘的直接产物）。

**「续用」以 loop 那次抽查为条件**：若抽中的三条里**再出现一条名不副实**，
则「误放行 = 1 次、且是孤例」不再成立，**本条须重判**。
