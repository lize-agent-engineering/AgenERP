## 2. 🔴 头号发现：出现了一次门禁误放行，而且持续了数日

### 2.1 它为什么是头号

`docs/audits/2026-08-23-CP9-P0-retrospective.md` 里，P0 复盘写死的判据之一逐字是：

> **门禁误放行（判 pass 但其实错）次数 = 0** —— ✅

**P1 产生了一个实例。** CP1 把「门禁误放行」列为头号风险，P0 判它没发生；
P1 发生了，且**不是被门禁发现的，是人手动跑了一次真解释才撞出来的**。

### 2.2 误放行的形态

判据 `test_the_user_in_the_answer_is_the_person_the_real_sid_resolves_to`
原本逐字：

```python
assert payload["answer"] or payload["accepted"] is False
```

**一个 `or`。** 模型拒绝时 `accepted` 恰好就是 `False` ⇒ **空答案照过**。

而 CI 里的实际情况是：路由器忽略 `AGENERP_LLM_MODEL`，改用第一个满足能力的
档案 `qwen3.8-max`，**而该模型没有免费额度** ⇒ 端点回 HTTP 403 ⇒ 每一次解释
都失败、每一次都回空答案 ⇒ **这条判据一路绿着**。

⇒ **那几天的「54 项全绿」，在「Agent 到底能不能答」这一维上是空的。**

### 2.3 三个 bug 互相咬着，单看任何一个都不致命

| # | 缺陷 | 单独看 | 三个叠加 |
|---|---|---|---|
| ① | `AGENERP_LLM_MODEL` 被 `route()` 忽略 | 「配置没生效」，可忍 | 走到没额度的模型 |
| ② | `RoutingError` 被吞，回包不带理由 | 「报错不友好」，可忍 | **没人知道它失败了** |
| ③ | 答案面判据的 `or` 逃逸 | 「判据偏松」，可忍 | **没人拦得住** |

**任何一条修掉，这次误放行都不会持续数日。**
这是「多条弱缺陷叠成一条强缺陷」的实例，值得单独记。
