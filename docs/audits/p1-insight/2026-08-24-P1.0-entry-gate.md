## 0. 承重命题与它测到的范围

**命题**：*确定性的循环门禁，能否补偿模型能力的不足？*

**本文件的结论只覆盖一道题**（恒锐动力数据集上的「成品仓压货」问题）、
两个模型、每格 3 次有效运行。plan §8 风险 ② 逐字写着「任何『门禁能补偿模型能力』
的一般化表述都是超纲的」——本文件不作任何这样的表述。

## 1. 网格结果（配置揭晓后）

| 格位 | 有效运行 | 正确 | 不完全 | 错误 |
|---|---|---|---|---|
| `qwen-plus`（弱）· 门禁 **off** | run-02 / run-05 / run-13 | **0** | 2 | 1 |
| `qwen-plus`（弱）· 门禁 **on** | run-04 / run-07 / run-11 | **2** | 1 | 0 |
| `qwen3.6-plus`（强）· 门禁 **off** | run-01 / run-06 / run-12 | **3** | 0 | 0 |
| `qwen3.6-plus`（强）· 门禁 **on** | run-03 / run-08 / run-14 | **3** | 0 | 0 |

逐条打勾见 `verdicts.md`；三条判据逐字取自 plan §2，跑之前已冻结。

## 2. H1–H4 逐条对照

判定用的聚合口径：**该格 3 次有效运行的多数**（≥ 2/3 命中记 `吻合`），
且未命中的那次必须点名。
⚠️ **这条口径是事后补的** —— plan §2 冻结了三条判据与判定协议，但**没有**冻结
「一格 3 次该怎么合成一条假设的判定」。照实登记为本轮的方法学缺口，不假装它一直在。

### H1 · 无门禁 + 弱模型 → 错法 A 或 B —— **不吻合**

依据：run-02 / run-05 / run-13。

H1 逐字是一个**合取式**：「将给出错法 A 或错法 B，**不会**自发地从 Bin 反查入库来源」。

- **前半吻合**：三次**没有一次**给出正确答案（0/3），失败方向与预测一致。
- **后半被证伪**：run-02 与 run-13 **确实自发地读了库存流水并逐笔点名了两张入库凭证**
  （run-13 逐字「2 月 5 日入库 1000 台 → 2 月 7 日又入库 1000 台（总计 2000 台）→
  2 月 8 日出库 990 台」）。它们**看见了那 1,000 台，却没有把它认成根因**——
  归因写成「销售订单状态被误解 / 还有 10 台没发」。

合取式有一个假的合取项即为假，**故 H1 记 `不吻合`**。
这不是措辞洁癖：H1 预测的失败机制是「**没查**」，实测的失败机制是「**查了但没归因**」。
两者对门禁该怎么设计的含义完全不同——前者要门禁**逼它去查**，
后者要门禁**逼它把查到的东西用上**。**现有 L3 恰好是后者**（它判的是
「答案里报了库存数 → 入库来源必须逐张 doc.get 覆盖」），这解释了为什么门禁在这道题上有效。

### H2 · 有门禁 + 弱模型 → 正确答案 —— **吻合（2/3）**

依据：run-04 ✅ / run-11 ✅ / run-07 ❌（不完全）。

- 同一个 `qwen-plus`，门禁 off 时 **0/3 正确**，门禁 on 时 **2/3 正确**。
  这是本实验唯一一处**门禁单独变量下的方向性差异**。
- **未命中的那次照实写**：run-07 的最终答案在「现在我可以给出最终回答了。」处**截断**，
  三条判据里的 ③ 一个字没写。它**不是**答错，是**没答完**——12 次工具调用、
  111,480 token，是弱模型格里 token 最高的一次。**门禁把它逼到了预算边缘**。
- ⚠️ **run-04 的命中带分歧**：它点名了外协那批多余（判据 ③ 按原文命中），
  但把机制说成「重复记账」，而站点上是真有两批实物。判据 ③ 未要求机制正确，
  本轮**不擅自加码**，分歧登记在 `verdicts.md`。若后续认为机制必须正确，
  该格降为 1/3，**H2 随之翻成 `不吻合`** —— 这个翻转点写在这里，不藏。

### H3 · 无门禁 + 强模型 —— **结果：3/3 全对**，按 H3 前一支执行

依据：run-01 / run-06 / run-12，三次全部命中三条判据。

H3 事先不预测，只写了两支处置。实测落在**前一支**，其原文是：

> 若它自发答对 → **H1 的失败模式与模型能力有关，而非与门禁有关**，
> 「门禁补偿能力」这个命题被削弱：更强的模型可能不需要门禁。

**照原文执行，不改口。** `qwen3.6-plus` 在**没有任何门禁**的情况下，
三次都自发地从 Bin 反查到两张入库凭证、并点名外协那批是积压根因
（run-06 逐字「外协那 1000 台并没有对应的发货单据来消耗」）。

### H4 · 门禁的代价可测且有上限 —— **吻合**

判据原文：**同一模型**下，门禁开的工具调用**中位数** ≤ 门禁关的**中位数 × 3**。

| 模型 | off 中位数 | on 中位数 | 上限（off × 3） | 结论 |
|---|---|---|---|---|
| `qwen-plus` | 5 | **10** | 15 | ✅ |
| `qwen3.6-plus` | 10 | **10** | 30 | ✅ |

**方向是收敛的，不是发散的**：最坏一格是 2.0×，离 3× 上限还有余量。
敏感性：把无效的 run-09（22 次调用）算进 `qwen-plus · off`，该格中位数 5 → 6，结论不变。

⚠️ **H4 只管工具调用次数，不管 token，别把它读成「门禁便宜」**：
`qwen-plus` 的 token 中位数 25,586（off）→ 78,915（on），**约 3.1 倍**；
`qwen3.6-plus` 84,942 → 85,182，**约 1.0 倍**。
弱模型侧门禁的 token 代价接近判据给工具调用设的那条 3× 线，而**判据没有约束它**。
这是判据的覆盖缺口，登记在此。

## 3. 与预期相反的结果

**有，两条。**

### ① H3 落在削弱命题的那一支 —— 强模型无门禁 3/3 全对

这是本实验最不利于承重命题的一条实测，**它不是噪声，是三次一致的结果**。
它直接推翻了「这道题结构性地需要门禁」这个读法：在 `qwen3.6-plus` 上，
所谓「外协批是孤儿、从订单侧不可见」的陷阱**根本没有绊住它**——
它自己就走到了 Bin，自己就逐笔追了流水。

### ② H1 的失败机制与预测相反 —— 弱模型不是「没查」，是「查了不用」

见 §2 H1。这条同样与起草时的图景相反：plan §1.3 把陷阱描述成
「一整批产出从订单侧不可见」，隐含的失败模式是**看不见**；
实测的弱模型**看见了**（run-02 / run-13 都把两张入库凭证列进了答案），
失败在**归因**那一步。

## 4. 承重命题的处置

> **处置：`被削弱`。**

**理由**（逐条对应实测，不外推）：

1. **门禁的效果在弱模型上是真的**：同模型、同提示词、同题目，门禁 off 0/3 → on 2/3。
   这是唯一变量为门禁的一组对照，**不能被 H3 抹掉**。
2. **但「补偿能力不足」这个说法在本题上站不住**：`qwen3.6-plus` 无门禁 3/3。
   门禁在这道题上**没有**做到「让弱模型追上强模型」——弱模型加门禁是 2/3，
   强模型不加门禁是 3/3。门禁缩小了差距，**没有抹平**。
3. 因此本题支持的最强表述是：**「在这道题上，门禁把弱模型的正确率从 0/3 提到 2/3，
   但仍低于强模型无门禁的 3/3。」** 到此为止，不再往前一个字。

**备选解释（必须与结论并列，不许只留一条）**：

- **(甲) 题目难度被 T0 的 (a) 降了一档**（plan §8 风险 ⑤）：装载器补送了
  `Work Order.sales_order`，于是从订单出发 `doc.links` 能看到自制工单，
  「外协是孤儿」成了**唯一**不可见项。难度更高的版本（工单也挂不回去）下，
  强模型是否仍 3/3 **本实验答不了**。H3 的结果对难度敏感，这一条不能排除。
- **(乙) 门禁可能过拟合到这道题**（plan §8 风险 ③）：L3 是照着这个陷阱设计的。
  缓解是措辞通用 + 一条无关合成轨迹反测，**残余未消除**。
- **(丙) 强制续跑消息的强度是下界**（plan Phase 2 的就地裁定）：门禁只说「缺几件」，
  不说「缺哪几件」。更强的提示会不会把 2/3 推到 3/3，本实验没测。
- **(丁) n = 3，只够看方向**（plan §4 Non-Goals 第 5 条）：0/3 与 2/3 的差
  在这个样本量下**不构成比率估计**，只构成方向。

**对 P1.7「单次解释成本上限」的影响**（plan §0 指定要答的那一问）：

- 「便宜模型 + 强门禁」这条路**不能按等价替代来做成本模型**：本题实测，
  弱模型开门禁的正确率仍低于强模型不开门禁，且 token 代价约 3.1×
  （25,586 → 78,915 中位数），**同时**还有一次因预算边缘而答案截断（run-07）。
- 强模型这一侧的读数正相反：门禁的 token 代价约 1.0×（84,942 → 85,182）。
  **若 P1.7 要设单次解释成本上限，本题的数据支持「强模型 + 门禁」而不是
  「弱模型 + 门禁」** —— 后者省的是单价，费的是轮次，且质量没追上。
- ⚠️ 这是**一道题上的读数**，不是成本模型的结论。P1.7 要用它必须再取样。

## 5. 与命题无关但必须登记的两件事

1. **无效运行 2 次，均为 token 超限**（run-09 / run-10，上限 200,000）。
   同格无效最多 1 次，未触及 plan §2 的「> 3 次即停下写 STATE §3」上限。
   两份无效轨迹原样留在仓库，未删未改。
2. **盲判没做到**：判定者与执行者是同一个循环，且打勾前已看过配置汇总表。
   `verdicts.md` 开头逐字记了这件事。**本文件的所有判定按此折价** ——
   判据本身是跑之前冻结的，逐条命中/未命中全部落盘可复核，
   但「事后挪标准」这一风险**只被削弱，没有被消除**。
