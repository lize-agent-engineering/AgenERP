# 预期红名单 —— 判据已写、实现未到的门禁测试。
#
# CI 的 `gates` job 用它把「故意的红」和「真的坏了」区分开：
#   · 名单内的测试红   → 正常，CI 绿
#   · 名单内的测试却绿 → **失败**（名单过期了，实现已到位就该把它从名单里划掉）
#   · 名单外的测试红   → **失败**（真的坏了）
#
# 棘轮方向：这个名单**只能变短**。变长 = 有人把一个真失败塞进来充当「预期」，
# CI 的 `expected-red-ratchet` job 会拦下，除非提交信息里带人工批准：
#   Gates-Change-Approved-By: <姓名>
#
# ⚠️ 2026-08-21 从 tests/gates/ 挪到这里，原因是循环实测撞出的一个真矛盾：
#    build-verify prompt、判定器输出、gate-verify 的失败回灌 —— 三处都命令 loop
#    「测试转绿就把它从名单里划掉」，而 AGENTS.md 红线 1 又禁止碰 tests/gates/** 下的
#    任何文件。循环没有自己找理由绕过，而是停下来写了交接文档等人（做得对）。
#
#    分清两件事就解开了：**测试代码是裁判，名单只是「哪些裁判现在预期是红的」的账本。**
#    裁判仍受红线保护（一个字都不许改）；账本允许 loop 在同一提交里划掉已转绿的行，
#    棘轮 job 保证它只能变短。账本变长仍需 Gates-Change-Approved-By: 人工批准。
